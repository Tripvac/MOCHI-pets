# Размещение MOCHI

Репозиторий содержит исходники. Публикация кода на GitHub сама по себе не включает сайт, API или Telegram-бота.

## Только одиночная игра

1. Установите Node.js 22+.
2. Выполните `npm ci` и `npm run build`.
3. Разместите содержимое `dist` в корне статического HTTPS-сайта.
4. Проверьте загрузку `art`, `audio`, `fonts` и `widgets`, затем запустите игру на телефоне.

Этот вариант сохраняет прогресс в браузере. Общего дома на чисто статическом хостинге нет. Настройки содержат пункт общего дома, но он сообщит об отсутствии API.

Приложение использует пути `/art`, `/audio`, `/fonts`, `/widgets` и `/api`. Для GitHub Pages в подпапке `/<repository>/` требуется адаптировать и сборку, и обращения к ресурсам; одной настройки `base` в Vite недостаточно. Автоматическое развёртывание Pages не настроено.

## Сервер общего дома

Текущий сервер — прототип для локальной сети. Схема ниже описывает его техническое размещение; перед открытием для пользователей выполните доработки авторизации из [INTEGRATION.md](INTEGRATION.md).

1. Установите зависимости и соберите фронтенд: `npm ci`, `npm run build`.
2. Передайте серверу `MOCHI_HOST=0.0.0.0`, порт через `PORT` или `MOCHI_PORT`, а `MOCHI_DATA_DIR` направьте в постоянный каталог.
3. Запустите `node server.mjs`. Сервер отдаёт `dist` и API с одного origin.
4. Настройте HTTPS перед Node.js средствами хостинга или reverse proxy. Внешний адрес должен быть доступен обоим участникам.
5. Обеспечьте сохранение каталога данных при пересборке и перезапуске. Временная файловая система хостинга для домов не подходит.

Пример для macOS / Linux:

```bash
MOCHI_HOST=0.0.0.0 MOCHI_PORT=3000 MOCHI_DATA_DIR=/var/lib/mochi node server.mjs
```

Каталог должен существовать либо быть доступен процессу для создания. В production используйте менеджер процессов хостинга и резервные копии. Не запускайте несколько экземпляров этого JSON-сервера с одной базой.

`GET /api/health` отвечает `{"sharing":true,"version":3}`. Проверка этого адреса подтверждает доступность процесса, но не проверяет все игровые действия или постоянство хранилища.

## Telegram

В BotFather укажите публичный HTTPS-адрес в настройках кнопки меню Mini App. Подключение кнопки не добавляет авторизацию пользователей: проверка подписи `initData`, срока `auth_date`, Telegram-сессий и членства в доме реализуется на сервере отдельно.

Не добавляйте токен бота в frontend, `VITE_*`, README, GitHub Issues или коммиты. Текущий проект не требует токена для локальной работы. Подробности — в [TELEGRAM.md](TELEGRAM.md).

## Ссылка открытия игры из виджета

В `phone-widget/src/main.mjs` замените `GAME_URL` на свой доступный HTTPS-адрес. Затем выполните:

```bash
npm run widget
npm test
npm run build
```

Если нужен автономный HTML, дополнительно выполните `npm run standalone`. Импортируйте новый установочный файл в Scriptable. Сама передача потребностей в текущем виджете остаётся ручной.

## Что проверить после размещения

- Вступление, выбор друга, локальное сохранение после перезагрузки страницы.
- Обе комнаты, покупки, установка и перенос мебели, одежда каждого персонажа.
- Дождь и снег только за окном, ночь и настольный свет, звук после касания.
- Создание общего дома и присоединение второго устройства; покупки и уход с двух экранов.
- Сохранность дома после перезапуска и повторного развёртывания сервера.
- Telegram на iPhone и Android: безопасные отступы, клавиатура, «Назад», сворачивание и возврат.
- Установка виджета, импорт потребностей, корректная ссылка по нажатию.
