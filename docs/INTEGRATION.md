# Сервер и следующий этап интеграции

В сборке уже есть общий дом для локальной сети. Клиент и Node-сервер используют одну модель `shared/game.mjs`. В автономном HTML работает локальный режим; общий дом требует запуска `server.mjs` и открытия игры по его адресу.

## Реализованный API

| Метод | Адрес         | Тело / результат                                            |
| ----- | ------------- | ----------------------------------------------------------- |
| GET   | `/api/health` | `{sharing:true,version:3}`                                  |
| POST  | `/api/create` | `{state:{species,name},actor}` → новый `{code,state}`       |
| POST  | `/api/state`  | `{code}` → актуальное `{state}`                             |
| POST  | `/api/action` | `{code,requestId,expectedVersion,action}` → новое `{state}` |

Создание дома начинает нового общего питомца; сервер не импортирует присланные монеты и инвентарь. Действия: `feed`, `pet`, `play`, `sleep`, `buy`, `equip`, `game`, `claim`, `rename`, `companion`. Сервер применяет время, цены, расход предметов, допустимость действий и награды через общие правила. Повторный `requestId` не применяет действие второй раз. При устаревшем `expectedVersion` возвращается HTTP 409 с актуальным состоянием; клиент один раз повторяет действие на новой версии. Опрос выполняется каждые 3 секунды.

Переменные окружения: `MOCHI_PORT` (по умолчанию 3000), `MOCHI_HOST` (по умолчанию `127.0.0.1`), `MOCHI_DATA_DIR` (по умолчанию `.mochi-data` у сервера). Сохранение JSON атомарно для одного процесса. Не запускайте несколько процессов с одной базой. Код дома — секрет доступа, не пароль учётной записи. Имя участника — подпись событий, не проверенная личность.

## Перед публичным запуском

Нужны проверка Telegram `initData` на сервере и сроков `auth_date`, сессии участников, приглашения с ограниченным сроком, проверка членства в доме и ограничения частоты запросов. Токен бота и административные ключи базы остаются на сервере. Нельзя доверять `initDataUnsafe` для авторизации.

Текущий LAN-сервер проверяет формулу награды, но принимает очки мини-игр от клиента. Для публичной экономики добавьте серверные игровые сессии, уникальный одноразовый финиш и проверку результатов. Перенесите JSON в транзакционную БД и настройте резервные копии. Клиентский код и список предметов можно сохранить.

При использовании Supabase понадобятся таблицы домов, участников, питомцев, инвентаря, игровых сессий, полученных достижений и запросов действий, а также RLS по членству. Покупки, кормление и награды обновляются одной транзакцией. Realtime может заменить опрос; цены и право списания валюты остаются на сервере.

Погода по кнопке и в автоматическом режиме раз в 15 минут запрашивается прямо из Open-Meteo для Алматы, без геолокации пользователя. Ручные эффекты ясной погоды, облаков, дождя и снега доступны офлайн. Для нескольких городов добавьте выбор города и серверный кэш. Напоминания потребуют отдельной настройки рассылок и серверного расписания. Платежи не подключены.

## Виджет iPhone

В версии 9 включён установочный файл виджета Scriptable: питомец, потребности или оба режима. Инструкция — в `phone-widget/README_RU.md`. Собственного приложения iOS и расширения WidgetKit нет.

Передача состояния из игры в Scriptable выполняется вручную. Экспорт содержит имя, вид питомца, его портреты и прогноз потребностей на 48 часов; код дома, инвентарь, монеты и история не передаются. Для автоматической синхронизации потребуется отдельный защищённый серверный метод и привязка виджета к разрешённому пользователю; текущий скрипт не выполняет сетевых запросов.
